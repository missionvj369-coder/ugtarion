# Security Policy

## Universal Guard Trust — UGTarion

Universal Guard Trust takes security seriously.

UGTarion includes authentication, database integration, security controls, rate limiting, validation, session management and other infrastructure. Security issues can affect users, contributors, data and connected services.

## Supported Development

Security fixes should be applied to the actively maintained `main` branch and to the current production version where appropriate.

Older versions may not receive security fixes.

## Reporting a Vulnerability

Please report suspected security vulnerabilities privately.

### Security Contact

security@ugtglobal.space

Do not publicly disclose a vulnerability before the UGT technical team has had an opportunity to assess and address it.

A useful report should include:

- Description of the issue
- Affected component
- Steps to reproduce
- Expected behavior
- Actual behavior
- Potential impact
- Relevant logs or screenshots where safe
- Suggested mitigation, if known

Please do not include passwords, API keys, authentication tokens, private user information or other secrets in the report.

## Examples of Security Issues

Examples include:

- Authentication bypass
- Authorization failures
- Supabase/RLS vulnerabilities
- Exposure of service credentials
- API key leakage
- Cross-site scripting
- Injection vulnerabilities
- CSRF vulnerabilities
- Session/token vulnerabilities
- Sensitive data exposure
- Unsafe file or command execution
- Dependency vulnerabilities with meaningful impact
- Server-side security issues

## Responsible Disclosure

Please give the project maintainers reasonable time to investigate and remediate a confirmed vulnerability before public disclosure.

We will work to:

1. Confirm the report.
2. Assess severity and scope.
3. Reproduce the issue where possible.
4. Develop and test a fix.
5. Deploy the mitigation where appropriate.
6. Document the resolution when safe.

## Secrets

Never commit:

- `.env`
- `.env.local`
- production credentials
- Supabase service-role keys
- private API keys
- passwords
- private tokens
- private certificates
- private cryptographic keys

Use environment variables or an appropriate secret-management system.

## AI-Assisted Development

AI-generated code must be reviewed and tested before deployment.

AI systems must not be given unnecessary access to:

- production credentials
- private user data
- authentication secrets
- unrestricted production infrastructure

AI-generated code must not be assumed secure simply because it was generated by an AI system.
